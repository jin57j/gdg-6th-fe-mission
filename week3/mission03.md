fetch 와 axios
fetch는 브라우저에 기본 내장된 순정 내장 함수이다. 별도의 설치나 라이브러리 추가 없이 즉시 사용 가능하며 자바스크립트 번들 용량을 증가시키지 않는다.

Axios는 개발자들이 더 편하게 비동기 통신을 할 수 있도록 기능을 추가한 외부 라이브러리이다. 설치가 필요하지만 편리한 부가 기능과 자동화 처리를 많이 제공한다.
    

1. GET (데이터 조회)
 서버에 있는 데이터를 요청하는 방식이다. 유저 목록을 보거나 게시글 읽기가 이에 해당한다. 주소창에 URL을 치고 들어가는 것과 완벽히 같다.

특징: 서버의 데이터를 바꾸지 않고 오직 읽기만 한다. 주소창 뒤에 데이터가 다 노출되기 때문에 비밀번호 같은 민감한 정보를 보낼 때는 절대 쓰면 안 된다.

fetch: 서버에서 데이터를 받아왔지만, 데이터가 아직 문자로 압축된 상태이다. .json()이라는 메서드를 거쳐 한 번 더 거쳐야만 실제 데이터를 꺼내 쓸 수 있다.

Axios: 데이터를 받아오는 순간, 서버가 보낸 데이터가 JSON(문자 데이터)인 것을 눈치채고 알아서 자바스크립트 객체로 즉시 변환해 둔다. 개발자는 변환 과정을 기다릴 필요 없이 바로 내용물을 꺼내 쓰면 된다.

2. POST (데이터 생성)
서버에 새로운 데이터를 만들어주라고 요청하는 방식이다. 회원가입을 하거나, 글을 새로 쓰거나, 사진을 업로드할 때 사용한다.

특징: 보내야 할 데이터(본문)가 필수적이다. 주소창에 데이터가 남지 않고 숨겨져서 가기 때문에 GET보다 안전하다.

fetch: 내가 가진 자바스크립트 데이터 압축해야 한다. fetch를 쓰면 이 (JSON.stringify)를 사용해야한다  서버에게 헤더 설정도 일일이 수동으로 달아주어야 한다.

Axios: 그냥 보낼 데이터 객체를 주기만 하면 끝난다. Axios가 내부에서 알아서 데이터를 문자열로 압축하고, 헤더까지 자동으로 세팅해서 서버로 안전하게 배달해 준다.

3. PUT (데이터 수정)
서버나 데이터베이스에 이미 저장되어 있는 기존 데이터를 다른 내용으로 수정(덮어쓰기) 요청하는 방식이다. 회원 정보 변경이나 글 수정이 이에 해당한다.

특징: POST와 마찬가지로 서버에 수정할 데이터를 실어서 보내야 하므로 본문 데이터와 헤더가 똑같이 필요하다.

fetch와 Axios의 차이:

fetch: POST 때와 마찬가지로 수정할 데이터를 직접 문자열로 압축하고 헤더 설정을 해야한다.

Axios: PUT 전용 기능을 제공하므로, 어떤 대상을 수정할지 지정한 뒤 수정할 데이터 객체를 넘겨주면 압축과 헤더 지정이 한 번에 자동 처리된다.

4. DELETE (데이터 삭제)
쉽게 말해: 서버에 저장된 데이터를 지워주라고 요청하는 방식이다. 게시글 삭제나 회원 탈퇴가 이에 해당한다.

특징: 어떤 대상을 지울지 주소(URL)에 명시하기 때문에, GET 방식처럼 대개 보낼 데이터 본문이 비어있다.

fetch와 Axios의 차이:

fetch: 기본 설정이 데이터를 가져오는 GET으로 고정되어 있기 때문에, 데이터 DELETE 설정을 반드시 수동으로 적어서 알려주어야만 서버가 알아듣고 지워준다.

Axios: 삭제 전용 기능에 지울 대상 주소만  던져주면 삭제 명령을 수행한다.
