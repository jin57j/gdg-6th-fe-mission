동기 (Sync): 설계가 직관적이지만, 앞선 작업이 끝날 때까지 뒤의 작업들이 모두 Blocking됨. 때문에 하나의 작업이 서버 통신 등으로 3초간 멈추면 웹페이지 전체가 얼어붙는다는 단점이 존재한다.

비동기 (Async): 요청을 던져놓고 결과가 오기 전에 다음 작업을 바로 실행한다. 시간이 오래 걸리는 네트워크 요청, 타이머 등을 백그라운드에 맡겨두고 다른 일을 먼저 처리하므로 자원을 극대화하여 사용할 수 있다는 장점이있다.

콜백 함수 (Callback) 비동기 함수 호출 시 작업이 완료되면 실행되는 뒤처리용 함수를 직접 인자로 넘겨주는 방식이다. 단점 : 콜백 헬이라 일커어지는 현상으로 비동기 결과를 처리하기 위해 또 다른 비동기 콜백을 중첩하면서, 코드가 오른쪽으로 거대하게 밀리는 피라미드 구조가 형성된다. 이는 가독성을 해치며, 코드의 제어권을 외부함수에 넘겨주기에 에러 발생 여부나 함수 실행 횟수를 내가 통제할 수 없다는 단점이있다.

프로미스 (Promise) 비동기 작업의 최종 결과를 담겠다고 약속하는 미래의 값을 인자로 보내주는 방식이다 . 장점: 콜백 방식과 달리 함수를 넘겨주는 것이 아니라, 호출 즉시 Promise라는 값(객체)을 내가 직접 넘겨받아 통제하여 기존 문제를 해결하였다. 명확한 상태 관리로 Pending(대기), Fulfilled(성공), Rejected(실패)로 작업 상태가 확실하게 보장된다. 또한 .then()의 특성으로 코드가 옆이 아닌 아래로만 흐르는 구조로 바뀌기에 가독성을 유지할 수 있다.

Async / Await 프로미스를 기반으로 작동하되, 개발자가 코드를 작성하고 읽을 때는 마치 동기 코드처럼 보이게 만든 문법이다. 장점: 함수 단위 일시정지를 한다 이는 async 함수 내부에서 await를 만나면 프로미스에서 실제 값이 도출될때까지 해당 함수만 잠시 멈춘다. 장점: 비동기 특유의 복잡한 .then() 체이닝을 생각할 필요 없이, 위에서 아래로 한 줄씩 직관적으로 읽힌다. 함수 내부는 await로 멈춰서 순서(동기식 가독성)가 보장되지만, 함수 밖의 코드는 여전히 비동기로 돌아간다고 할 수 있다
